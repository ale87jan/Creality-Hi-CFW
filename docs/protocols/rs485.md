# Bus RS-485 (`/dev/ttyS5`, 230400 8N1)

Bus compartido por los motores de lazo cerrado y el CFS. Fuentes: código abierto de la K2
(`serial_485.py`, `motor_control.py`, `box_protocol.py` de `Jacob10383/k2-plus-custom-firmware`), el
`auto_addr_wrapper.py` legible de la Hi y pruebas con `tools/hi_probe.py`. Confianza: **[P]** probado en la Hi,
**[F]** leído en código o firmware, **[I]** inferido.

## Trama [P]

```text
F7 | addr | len | status | func | payload ... | crc8
```

- `len` = longitud del payload + 3 (cuenta `status`, `func` y `crc8`). Trama completa = `len` + 3 bytes.
- `crc8`: polinomio 0x07, valor inicial 0, sin reflexión (CRC-8/SMBUS), calculado sobre `len..payload`
  (sin `F7` ni `addr`).
- Petición del host: `status` = 0x00 (motores, auto-dirección) o 0xFF (órdenes de caja del CFS en la K2 [F]).
- El transceptor puede devolver el eco de la propia petición: hay que descartarlo.

## Direcciones

| Dirección | Dispositivo | Fuente |
| - | - | - |
| 0x01-0x04 | Cajas CFS | [F] |
| 0x11 | Lector RFID externo (K2) | [F] |
| 0x21 / 0x22 | Módulos de correa X/Y (K2) | [F] |
| 0x81 / 0x82 | Motor X / motor Y de la Hi | [P] |
| 0x83 / 0x84 / 0x85 | Motor Z / Z1 / E (K2) | [F] |
| 0xFE / 0xFF | Broadcast | [F] |

## Motores

### Asignación de dirección [F]

Cada driver toma su dirección de los niveles físicos de sus pines STEP/DIR cuando recibe el broadcast
`READ_ADDR` con payload `01` en 0xFF: `addr = 0x81 + DIR + 2·STEP`. El código de la K2 fija x=0x82 e y=0x81;
la Hi de stock deja X=0x81 e Y=0x82 [P].

### Funciones

| Func | Nombre | Payload | Uso | Fuente |
| - | - | - | - | - |
| 0x03 | ENCODER_CALIBRATE | — | Calibración del encoder (**escribe en el driver**) | [F] |
| 0x04 | ELEC_OFFSET_CALIBRATE | — | Calibración del offset eléctrico (**escribe**) | [F] |
| 0x06 | SYS_PARAM | `01 id valor` escribir RAM, `02 id` leer, `03` aplicar | Parámetros en RAM | [P] lectura; [F] resto |
| 0x07 | FLASH_PARAM | `05` escribir, `06` leer, `03` guardar | Parámetros en flash (**persistente**) | [F] |
| 0x08 | GET | — | Estado | [F] |
| 0x0C | PROTECTION | `0B` consultar errores, `05` borrar | Errores y avisos | [F] |
| 0x0E | READ_ADDR | `02` leer dirección, `01` (a 0xFF) asignar | Dirección | [P] `02`; [F] `01` |
| 0x0F | TRANSPARENT | — | Túnel (K2) | [F] |
| 0x11 | STALL_MODE | modo | Modo de stall para homing (1 homing, 2 normal) | [F] |

Bits de `status` en las respuestas: 0x01 stall, 0x02 error, 0x04 aviso [F].

## CFS [F]

### Auto-dirección

| Func | Destino | Payload | Uso |
| - | - | - | - |
| 0xA1 | 0xFE | `FE FE` | Descubrir cajas |
| 0xA0 | 0xFE | `addr` + UID (12 bytes) | Asignar dirección |
| 0xA2 | caja | — | Comprobar si está en línea |
| 0xA3 | caja | — | Tabla de direcciones (solo Hi) |
| 0x0B | 0xFF | `01` | Pasar de bootloader a aplicación |

Respuesta: `dev_type` (1), modo (0 app, 1 bootloader) y UID de 12 bytes.

### Órdenes de caja (código K2, sin verificar en la Hi)

difieren de las de la K2 (`0x0A` responde 4 bytes, existe `0x0F`, cambian `0x0D` y `0x11`). Comparación
